# 저장 오류와 복구

앱은 프로젝트 루트의 `state.json`을 사용한다. 오류가 나면 먼저 터미널 메시지, 발생한 메뉴나 작업, 파일 존재 여부를 기록한다. 문제를 공유할 때는 저장 파일 전체 대신 오류 메시지와 재현 순서를 남긴다.

| 상황 | 앱의 동작 | 사용자 대응 |
| --- | --- | --- |
| 파일이 없는 첫 실행 | 기본 퀴즈로 시작한다. | 문제를 추가하거나 첫 풀이를 마치면 저장 파일이 생성된다. |
| JSON 문법·인코딩 오류 또는 필드 값 오류 | 읽기 실패를 알리고 메모리에서 기본 문제로 시작한다. | 새 저장을 유발하는 문제 추가나 풀이 전에 원본을 보관하고 아래 복구·초기화 중 하나를 선택한다. |
| 파일을 읽을 권한이 없거나 다른 프로그램이 잠금 | 읽기 실패를 알리고 메모리에서 기본 문제로 시작한다. | 올바른 프로젝트 폴더인지 확인하고 잠금을 해제하거나 접근 권한을 확인한 뒤 다시 실행한다. |
| 자동 저장 또는 파일 교체 실패 | 오류를 표시하고 메모리의 변경을 유지한다. 종료 시에도 저장을 한 번 더 시도한다. | 게임이 열려 있는 동안 쓰기 권한, 디스크 여유 공간, 파일 잠금을 확인한다. 필요하면 새로 입력한 문제를 따로 기록한 뒤 종료한다. |
| 종료 시 재시도도 실패 | 저장 오류 메시지를 표시한 뒤 종료한다. | 다시 열면 마지막으로 저장에 성공한 데이터가 불러와진다. 새 파일이 한 번도 저장되지 않았다면 기본 퀴즈에서 시작한다. |

## 손상 파일 처리 선택

1. **기존 기록 복구** · 게임을 닫고 손상된 `state.json`을 별도 이름으로 복사한다. 정상 백업이 있으면 이를 `state.json`으로 복원한다. 백업이 없으면 복사본에서 문제 배열과 최고 점수의 형식을 수정한 뒤 교체한다. 다시 실행해 목록과 점수를 확인한다.
2. **기본 문항으로 초기화** · 게임을 닫고 `state.json`의 이름을 `state.broken.json`처럼 변경한다. 다시 실행하면 기본 문항으로 시작하고, 다음에 저장하는 변경이 새 `state.json`에 기록된다.

JSON 문법만 검사하려면 프로젝트 루트에서 `python -m json.tool state.json`을 실행한다. 문법이 유효해도 선택지 수나 정답 범위 같은 필드 규칙은 게임을 다시 실행해 확인한다.
